# Performance

Found with `npm run perf` (qa/perf.mjs): production build, hidden windows under the test hook, median of 3 runs,
local fixture pages. Settings for every metric are in `qa/out/perf-results.json`; before and after medians are in
`qa/perf-baseline.json`. `npm run perf -- --compare` fails when a metric is more than 25 percent worse than the
latest medians there.

| P-001 | 2026-11-14 | idle_cpu_10_bg_tabs_pct | Every tab view reports `document.visibilityState` "visible" in the hidden test window, whether attached, detached or never attached, so the 7 warm background tabs run their timers and animations at full rate (about 3 percent of a core per fixture page, plus about 14 percent in the GPU process). Hiding detached views with `View.setVisible(false)` and turning background throttling back on for the shell and overlay changed nothing here: Chromium ignores hidden updates for a WebContents that was never shown, and the test window never is. Needs a check in a shown window; a tab opened in the background and never shown probably stays "visible" in normal use as well. | 34.3 % | - | open | - |
| P-002 | 2026-11-14 | heavy_tab_switch_ms, heavy_ui_cpu_10_opens_s | Every state broadcast sent the whole state, archive included (up to 2000 entries, most of a long-used profile's state), to the sidebar, which never shows the archive, and to the overlay, which renders nothing while detached. Each send is a structured clone, so tab switches and page loads got slower as the archive grew. The sidebar now gets the state without the archive; the overlay gets it while attached plus one last update after it detaches, and reads it itself when it loads. | 11.0 ms, 0.3 CPU s | 6.1 ms, 0.1 CPU s | fixed-unverified | 6ef4391 |
